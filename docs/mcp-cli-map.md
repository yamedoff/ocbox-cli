# Hosted MCP tools and the CLI commands that answer them

This map covers every tool in the hosted MCP registry (`MCP_TOOLS` in
`apps/api/src/mcp.ts` of the opencloudbox repository) and the `ocbox` command
that does the same work. The reason codes are the closed catalogue in
`apps/api/src/productFailures.ts`; they are the values a client reads in
`error.reasonCode` (or, for a 200 answer such as `gpu_check`, in the answer's
`reason` fields).

The MCP input names are listed with their units. The commands added by this map
take those names as kebab-case flags: `lifetimeSeconds` is
`--lifetime-seconds`, `memoryMib` is `--memory-mib`, and so on. The exception is
`ocbox preview create`, which takes `--session` for MCP's `sessionId`. The
Session, execution and operation read commands take the ID as a positional
argument (`<session-id>`, `<execution-id>`, `<operation-id>`). Existing commands
keep their established flags and units; the differences are listed under "Where
the CLI command is not a literal one-to-one". Every command below supports
`--json` and `--jsonl` with the same stable envelope as the rest of the CLI.

Every mutating MCP tool requires `idempotencyKey` in the arguments (or an
`Idempotency-Key` HTTP header). The matching CLI command has
`--idempotency-key`; when it is omitted the CLI generates a fresh UUID.

## Where the CLI command is not a literal one-to-one

- `project_list`: the CLI lists newest-first and has no `--order` flag. Use the
  hosted API directly when `order=oldest` is required.
- `project_delete`: `--project-id` defaults to the workspace's
  `opencloudbox.toml`; without `--yes` the command prompts on a terminal and
  refuses otherwise. The CLI does not send MCP's `confirmInUse`; the REST route
  accepts that confirmation only for compatibility, and a project with a live
  box is refused either way. Destroy the project's boxes first.
- `session_list`: `ocbox session list --project-id` calls the project REST
  route (`GET /v1/projects/{projectId}/sessions`), and `ocbox session list`
  without `--project-id` calls the owner-wide `GET /v1/sessions` route. Both
  list Sessions created over MCP or on another machine, and both follow
  `nextCursor` with `--cursor`. The `More:` line repeats `--project-id` only
  when one was given, and otherwise keeps just `--cursor`, `--limit` and
  `--include-destroyed`. `ocbox ls` still lists only the Sessions this machine
  tracks and their Sandbox bindings.
- `session_start`, `session_pause`, `session_stop`, `session_destroy` and
  `execution_start`: `ocbox start`/`pause`/`stop`/`destroy`/`exec` resolve only
  Sessions this machine tracks. `ocbox start` has no `start --session` flag: it
  starts the selected tracked Session, so select another tracked one with
  `ocbox use <session-id>` first. A Session created over MCP or on another
  machine is not tracked, so `ocbox use <session-id>` fails for it; use the MCP
  tool (or the REST route) until the CLI tracks that Session. On a hosted box,
  `ocbox pause` is refused because the hosted service cannot preserve memory;
  use `ocbox stop`, which keeps the filesystem, then `ocbox start`.
- `execution_start`: `ocbox exec --timeout-seconds` sends MCP's
  `timeoutSeconds` unchanged. The millisecond `--timeout` is a hidden,
  deprecated alias that still works and warns; the two flags are mutually
  exclusive, so `--timeout 300000` and `--timeout-seconds 300` both mean five
  minutes. On the hosted provider, `ocbox exec` prints `execution <id> accepted`
  on stderr, so the ID works with `ocbox execution get` and `ocbox cancel`. The
  fake provider prints its local execution ID. The CLI always waits for
  the command to finish and streams its output, so it has no `wait` flag.
- `session_create`: the MCP `requestedSpec.memory` is in MiB, while
  `ocbox start --memory` is in bytes, matching the existing CLI resource flags.
  `ocbox start` has no `--gpu-type`, `--gpu-count` or `--disk-gib` flags; choose a
  GPU size from `ocbox sizes` with `--size` instead. `secretReferenceIds` comes
  from `sandbox.secretReferenceIds` in `opencloudbox.toml`; `ocbox start` has no
  flag for it.
- `source_sync_plan`, `source_sync_apply` and `source_push_files`: the CLI's
  `ocbox sync push` owns manifest construction, planning and apply as one
  command, so there is no separate plan-only or inline-files command. The CAS
  v2 manifest is built from the local workspace and validated by the CLI before
  it reaches the API.
- `source_read_snapshot`: `ocbox sync diff` reads the box snapshot and compares
  it with the local workspace; it does not expose the raw snapshot pages.
- `execution_get`: the CLI result envelope redacts command output (`stdout` and
  `stderr` become `[REDACTED]`). `ocbox exec` is the command that streams
  command output; `ocbox execution get` reports the execution state, exit code
  and failure reason, and the result kind. When the result route answers 409
  because a terminal execution's result is not ready yet, the CLI reports the
  execution without a result instead of failing with
  `api_execution_not_complete`.
- `preview_create`: the REST route answers with the Preview; the MCP tool also
  wraps it in an Operation. `ocbox preview create` prints the preview URL.
- `usage_list`: the hosted REST route pages owner-wide usage and has no
  `sessionId` filter, so the CLI validates the Session and then walks pages until
  it finds that Session's events or the cursor ends (bounded to 20 pages per
  call). The `More:` line keeps `--session-id` and `--limit`.
- `snapshot_create`, `snapshot_restore` and `snapshot_delete`: the CLI waits for
  the durable Operation by default, like `ocbox stop`; `ocbox snapshot save
  --no-wait` prints the operation ID and returns. `<box>` is a tracked Session
  ID and defaults to the selected Session, the same way `ocbox stop` and `ocbox
  exec` pick it. `snapshot_list` prints the snapshots in the order the route
  returns them (newest first), with `--json` carrying the same list.

## NOTES

- Every MCP tool variant is now mapped to a CLI command. The owner-wide
  `session_list` variant (no `projectId`) is `ocbox session list` without
  `--project-id`, which calls the owner-wide `GET /v1/sessions` route.
  The thirteen commands added for this map are `ocbox gpu check`,
  `ocbox execution get`, `ocbox operation get`, `ocbox operation cancel`,
  `ocbox preview create`, `ocbox session list`, `ocbox session get`,
  `ocbox usage list`, `ocbox wallet get`, `ocbox snapshot save`,
  `ocbox snapshot list`, `ocbox snapshot restore` and `ocbox snapshot delete`.
- `source_sync_plan` and `source_read_snapshot` are mapped to the existing
  end-to-end sync commands rather than new plan/snapshot commands. A plan-only
  command would make a caller hand-build the CAS manifest and page that the CLI
  already derives from the workspace, and it would duplicate the sync engine's
  validation.
- The CLI never invents a reason code. `gpu_check` returns its reasons in the
  200 answer; the other new commands pass the server's `error.reasonCode`
  through to the human and JSON error output unchanged.
